# Student Course Management API

## Stage 1 API Tutorial

**Technology:** PHP, NGINX, MySQL, Docker

---

# 1. Project Overview

The Student Course Management API allows students to:

- Register a student account.
- Log in securely.
- View all their courses.
- View an individual course.

The API uses PHP to process requests, MySQL to store information, and NGINX to receive HTTP requests.

---

# 2. Starting the API

Open a terminal in the project directory and run:

```bash
docker compose up -d --build
```

The API will be available at:

`http://localhost:8080`

To stop the containers, run:

```bash
docker compose down
```

---

# 3. Authentication

Some API endpoints require a bearer token.

Students receive a token after successfully logging in.

Include the token in the request header:

```http
Authorization: Bearer YOUR_TOKEN
```

The API checks the token to identify the student.

Requests without a valid token receive a `401 Unauthorized` response.

---

# 4. API Endpoint: Register a Student

**Method:** POST

**Path:** `/api/register`

**Authentication:** Not required

This endpoint creates a new student account.

### Request body

```json
{
  "name": "Alex Student",
  "email": "alex@example.com",
  "password": "Student123!"
}
```
---

### Successful response

**Status:** `201 Created`

```json
{
  "message": "User registered successfully",
  "user_id": 1
}
```

The API validates the information and securely hashes the password before storing it.

### Possible errors

- `400 Bad Request` — Missing or invalid information.
- `409 Conflict` — Email address is already registered.

---

# 5. API Endpoint: Student Login

**Method:** POST

**Path:** `/api/login`

**Authentication:** Not required

This endpoint verifies the student's email and password and generates a bearer token.

### Request body

```json
{
  "email": "alex@example.com",
  "password": "Student123!"
}
```

---
### Successful response

**Status:** `200 OK`

```json
{
  "message": "Login successful",
  "token_type": "Bearer",
  "token": "YOUR_GENERATED_TOKEN",
  "expires_at": "TOKEN_EXPIRATION_DATE"
}
```

The token is generated by the API. Keep it private and use it in the Authorization header for protected requests.

### Possible errors

- `400 Bad Request` — Missing login information.
- `401 Unauthorized` — Incorrect email or password.

---

# 6. API Endpoint: Retrieve All Courses

**Method:** GET

**Path:** `/api/courses`

**Authentication:** Required

This endpoint retrieves all courses belonging to the authenticated student.

### Request header

```http
Authorization: Bearer YOUR_TOKEN
```

### Successful response

**Status:** `200 OK`

---

Example:

```json
[
  {
    "id": 1,
    "user_id": 1,
    "course_name": "CSC 640",
    "course_code": "CSC640"
  }
]
```

Only courses belonging to the authenticated student are returned.

### Possible errors

- `401 Unauthorized` — Missing, invalid, or expired token.

---

# 7. API Endpoint: Retrieve One Course

**Method:** GET

**Path:** `/api/courses/{id}`

**Authentication:** Required

This endpoint retrieves one course using its ID.

### Example request

`GET /api/courses/1`

### Request header

```http
Authorization: Bearer YOUR_TOKEN
```
---
### Successful response

**Status:** `200 OK`

```json
{
  "id": 1,
  "user_id": 1,
  "course_name": "CSC 640",
  "course_code": "CSC640"
}
```

The API checks that the requested course belongs to the authenticated student.

### Possible errors

- `401 Unauthorized` — Missing, invalid, or expired token.
- `404 Not Found` — Course does not exist or does not belong to the authenticated student.

# 10. Database Structure

The project uses four MySQL tables.

| Table | Purpose |
|---|---|
| `users` | Stores student account information |
| `courses` | Stores courses belonging to students |
| `assignments` | Stores assignments associated with courses |
| `api_tokens` | Stores hashed authentication tokens and expiration dates |

---

# 11. Security Features

The API includes these security measures:

- Passwords are stored using PHP password hashing.
- Database queries use prepared statements.
- Login generates a random bearer token.
- Only a hash of the token is stored in the database.
- Tokens expire after 24 hours.
- Protected endpoints reject missing, invalid, or expired tokens.
- Students can only retrieve their own courses.
